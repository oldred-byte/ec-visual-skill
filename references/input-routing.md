# Input Routing

## Purpose

Before planning visuals, decide how much product information the user supplied and how strictly it should control the visual story. Do not let the default 5-head-image or 10-detail-page structure invent facts that the product image or user materials do not support.

## Image-Only Intake Question

If the user uploads product/reference image(s) but provides no product facts, selling points, parameters, target users, brand colors, or document, do not plan immediately. Ask one concise intake question before planning or generation unless the user explicitly says to skip questions or generate directly.

Use this meaning, adapted to the user's language:

"Do you have any other information to add, such as selling points, product information, parameters, brand colors, or a product document? If yes, please upload or send it. If not, I will produce the head images/detail pages from the product image, reference image, and my category understanding."

After the user answers:

- If they provide information or a document, route it through the completeness rules below.
- If they say no, continue with the Missing Information route.
- If they do not answer but explicitly asked to proceed, continue with the Missing Information route and state that assumptions are based only on the images.

Ask once. Do not repeatedly block the workflow for optional information.

## Check For Key Product Information

After inspecting the product image(s) and reference image(s), check whether the user supplied:

- Product name/category.
- Core selling points or messages they want expressed.
- Product parameters, ingredients, material, process, size, capacity, model, bundle, or usage constraints.
- Target users and usage scenarios.
- Brand colors or mandatory visual identity rules.
- Claims that require evidence, such as ratings, certifications, official status, medical/health effects, waterproof level, sun protection, anti-bacterial rate, or test data.
- Any fixed page/screen structure, such as "these 10 screens are already decided" or a per-screen direction list.

If the user provides no extra information, or asks to proceed directly, continue without blocking. Use visible evidence and category-generic empathy only.

## Preserve Existing Screen Directions

If the user supplies or has already approved a detail-page structure, treat that structure as the scaffold. Do not replace it with the default 10-screen sequence. The task becomes screen-by-screen expression translation:

- Preserve each screen's assigned direction, role, or selling-point area.
- Improve how that direction is expressed from a buyer's point of view.
- Decide what evidence and main subject best prove that screen.
- Keep claim safety: strengthen expression without inventing facts.

If the fixed direction is vague, clarify it inside the plan rather than changing the sequence. For example, "selling point A" can become "buyer should believe the blade cuts cleanly with fewer repeated passes" when the product and category support that reading.

## Completeness Routes

### Complete Information

Use this route when the user provides clear product facts, selling points, parameters, and must-express messages.

- Treat supplied facts as the source of truth.
- Preserve parameter wording where precision matters.
- Turn technical or flat statements into visual selling messages without changing factual meaning.
- Do not add alternative claims just to fill the 10-screen structure.
- If supplied facts conflict with the product image, surface the conflict before generation.

### Partial Information

Use this route when the user provides some facts or scattered notes.

- Keep all supplied facts.
- Rewrite awkward, technical, or plain statements into buyer-facing messages.
- Fill gaps with visible product details and soft category-generic use cases.
- Mark inferred points as inferred, not user-provided facts.
- Avoid numeric, certified, medical, official, or performance-specific claims unless provided.

### Missing Information

Use this route when the user provides only product image(s) and reference image(s).

- Infer product category, visible features, likely use scenarios, and user anxieties from the image.
- Build a conservative selling-point set around visible details, category-generic needs, and emotional/lifestyle value.
- Use "daily use", "easy to carry", "clean feel", "comfortable experience", or comparable soft language when appropriate.
- Do not invent specifications, ratings, certifications, price, official store status, medical effects, or exact performance data.

Missing information does not mean generic image planning. Still build a buyer-centered expression hypothesis:

- What would a buyer of this category worry about before purchase?
- What body moment, hand action, surface contact, storage action, result state, or scene would make the benefit feel real?
- Which claims must stay soft because no proof was supplied?
- Which screens should avoid full-product hero composition because the evidence lives in a detail, body contact, or usage moment?

## Document Extraction

When the user uploads a document or text block, extract it into:

- Hard facts: specifications, parameters, material, ingredients, process, capacity, size, model, bundle, included accessories.
- Priority messages: claims or ideas the user clearly wants emphasized.
- Expression candidates: useful but overly technical statements that should be translated into e-commerce language.
- Risk claims: certifications, medical/health effects, official awards, rankings, test data, exact percentages, waterproof/sunproof/anti-bacterial ratings, warranty, price, and other claims that need evidence.
- Brand assets: brand colors, typography notes, logo rules, forbidden colors, tone-of-voice rules.

Hard facts must not be altered. Expression candidates may be rewritten for clarity and conversion. Risk claims may be used only when the document explicitly supports them.

## Selling-Point Extraction

Build a short selling-point bank before planning images:

| Point | Source | Claim safety | Buyer meaning | Best proof direction |
|---|---|---|---|---|
| Supplied or inferred point | user/doc/visible/category-generic | safe/risky/unsupported | why the buyer cares | scene/macro/mechanism/comparison/parameter/trust |

Use this bank to decide which points deserve head images and which belong in detail-page screens. If there are fewer strong points than default screens, combine or simplify screens instead of inventing claims.

## Consumer-Angle Map

Before detail-page planning, translate the selling-point bank into a consumer-angle map. This is not a new page structure; it is the buyer-facing interpretation used inside each fixed screen direction.

Use this table:

| Point or screen direction | Buyer anxiety/desire | Consumer-facing promise | Evidence moment | Safe wording boundary |
|---|---|---|---|---|
| Product/user supplied/inferred point | What the buyer fears or wants | What the screen should make them feel or believe | The image moment that proves it | What cannot be said without proof |

Examples of evidence moments:

- Shaver "gentle/low irritation": face or neck skin contact, blade head gliding along a curve, shaved skin result. The full product may be secondary.
- Shaver "sharp blade": metal blade surface, hair/stubble cutting macro, blade mesh detail. The product body may be only a small context cue.
- Earbuds "wearing comfort": ear contact crop and natural wearing posture. The charging case may be secondary.
- Earbuds "portable": hand scale, pocket, bag, desk edge, or storage action. The exact size or weight must not be claimed unless supplied.

When a point is inferred rather than supplied, use soft copy and visual implication rather than hard claims. For example, "贴合面部轮廓" is safer than "怎么刮都不泛红" unless irritation data or brand claim support is provided.
